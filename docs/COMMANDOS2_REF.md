## 2. ★ 가장 중요한 구조 — 그림과 판정이 분리돼 있다

시나리오 정의 한 줄이 네 파일을 묶습니다. **[실측]**

```
ESCENARIOS[0] = { 배경   : *.Y64        ← 화면에 보이는 그림
                  가림   : *.MA2        ← 무엇이 무엇을 가리는가
                  판정   : *.SEC        ← 어디를 걸을 수 있는가
                  물     : *.H2O }      ← 물 표면
```

> **화면에 보이는 그림은 게임 규칙을 하나도 모릅니다.**
> → 우리도 96×96 격자를 판정용으로 그대로 두고, 그 위에 그림을 얹으면 됩니다.
> → "맵을 그림 한 장으로 받으면 안 된다"는 문제는 **그림으로 판정까지 하려 할 때만** 생깁니다.

압축 원리: 8×8 블록마다 56바이트. 4×4 사분면마다 "명암 계단" 20종 중 하나를 고르고, 픽셀마다 4비트 색인만 저장.
검증: 블록 경계 이음새 에너지 10.1 vs 내부 10.1 → **블록 아티팩트 없음**.

> **가져갈 것**: 64×64 타일 · 회전×줌 프리렌더 구조
> **버릴 것**: 코덱 자체. 2001년엔 JPEG/PNG가 마땅치 않아 직접 만든 것. 우리는 JPG/WebP를 씀.

### 원본은 3D로 만들어 2D로 구웠다 [추정, 근거 3개]
1. 나무 그림자의 방향·길이가 일관됨 (손으로 그려선 이 정도로 안 맞음)
2. 카메라 4회전이 전부 저장돼 있음 (같은 장면을 4번 손으로 그렸을 리 없음)
3. 가림 폴리곤이 **평면식(A,B,C,D)** 을 가짐 — 3D 기하에서 뽑아낸 값

## 5. 가림 마스크 (.MA2)

| 항목 | 훈련1 값 | 라벨 |
|---|---|---|
| 서브맵 | **4개** = 카메라 4회전과 1:1 | [실측] |
| 가림 폴리곤 | **91개** — 각각 평면식 + 2D 외곽선 | [실측] |
| 마스크 조각 | **351장** (회전별 90/85/88/88) | [실측] |
| 조각 최대 크기 | 355 × 335 px | [실측] |
| **가림 단계** | **2비트 = 4단계** | [추정, 근거 강함] |

4단계 근거: 351개 전체 통계로 평균 0.935 bit/px, 최대 2.124 bit/px. 최댓값이 2를 살짝 넘는 것은 원본이 2bpp이고 최악 케이스 RLE 오버헤드 6%가 붙은 것으로 가장 잘 설명됨. (1bpp면 오버헤드 112%로 비현실적, 8bpp면 압축률 과함.)

> **가림은 있다/없다가 아니라 4단계다.** 나무 뒤로 지나갈 때 완전히 사라지지 않고 비친다.

## 6. 물 (.H2O) — 그리고 조수가 없다는 확정

물은 **화면 좌표에 미리 구워 넣고 스캔라인 래스터화까지 끝낸 삼각형 판**입니다. **[실측]**

| 몸체 (=회전) | 정점 | 삼각형 | 스팬 | 줄 |
|---|---|---|---|---|
| 0 | 626 | 1,100 | 34,708 | 915 |
| 1 | 636 | 1,133 | 35,340 | 1,106 |
| 2 | 611 | 1,065 | 32,382 | 907 |
| 3 | 634 | 1,115 | 34,867 | 1,107 |

+ 256×256 팔레트 물결 텍스처 1장 (실사용 242색)
격자·높이맵·마스크·애니프레임 **전부 아님**.

**움직이는 것은 딱 하나** — 회전별 **텍스처 스크롤 속도 2D 벡터**. 프레임도 수위도 없음.

### ★ 조수 부재 — 확정 (부정 확인) [실측]

- 정점의 마지막 4개 float이 **모든 몸체·모든 정점에서 0**. **Z좌표 자체가 없음**
- `MAREA`(조수) · `NIVEL_AGUA`(수위) · `PROFUNDIDAD`(깊이) 식별자가 훈련1·훈련4·섬·잠수함 **어디에도 없음**
- 규칙 엔진 조건 11종·동작 6종 중 물을 건드리는 것 **0개**
- 수면 높이는 오직 배 자신의 흘수선으로만 등장 (침몰 시 수면 상승 속도)
- 물 모양 변경의 유일한 수단 = **다른 물 파일로 통째 교체** (일회성 A→B 스위치) [추정 — 포맷 구조상 다른 방법 불가능]

> **미션 내내 연속으로 변하는 수위는 코만도스 엔진에 없습니다.**
> 우리 조수는 흉내가 아니라 원본에 없는 것입니다. 그래서 **격자를 navmesh로 바꾸면 안 됩니다.**

좌석 하나가 담는 것: 탑승 동작(타는 사람의 물리상태별) · 앉은 자세 · 배 안 좌석 위치 · 하선 동작 · 플래그(그림/조타석)

**미션 판정도 담기로**: `대원 전원이 탈것 안에 있고 + 탈것이 탈출 구역 안에`
같은 조건 클래스를 그릇만 바꾸면 **수풀 은신 판정**이 됨.

**흔들림 파라미터**: 서로 다른 주기 두 축(속도 5.05 / 4.59)에 수직 성분(5.48)을 겹침. 최대 진폭 2.05.
**물보라**: 배 기준 4개 지점.
**고무보트는 소지품**: 사공이 짐으로 갖고 다니다 펼침 (부풀리기/접기/구멍남 상태 관리)

**하나의 명령이 의자·트럭·전차·대포·승강기·배를 전부 처리** (`들어가기`/`나오기`).

## 9. 경비 행동 스크립트 (.GSC)

경비의 "살아있음"은 똑똑한 AI가 아니라 **경비마다 붙은 짧은 연극 대본**입니다.
훈련1은 7.4 KB, 훈련4는 36 KB. 그게 전부입니다.

| | 훈련1 | 훈련4 |
|---|---|---|
| 그룹 | 5 | 12 |
| 스크립트 | 8 | 36 |
| 명령 어휘 | 15종 | **20종** |
| 저장 형태 | 컴파일 바이너리 | **평문 텍스트** |

### 명령 20종의 성격 [실측]

| 갈래 | 명령 |
|---|---|
| 이동 | 좌표로 이동 · **이름 붙은 위치로 이동** · 바라볼 각도 |
| 연기 | 애니 1회 재생 · **생활 애니 N틱 반복** · 자세 설정 · 자리에 앉기/일어나기 |
| 시간 | 대기 · 영구 대기 · **사건 대기** |
| 지각 | **두리번거림 정지** · 두리번거림 재개 · 경계 모드 전환 |
| 흐름 | 라벨 · 점프 · 조건 · 조건끝 · 변수 설정 · 스크립트 시작 |

**반응 플래그 4종**: 적 보면 반응 · 소리 들으면 반응 · 자리 이탈 가능 · **시체 처리하러 감**

### 대본이 실제로 하는 일 (구조만)

- **담배 피는 상병**: 정해진 자리로 걸어가 → 각도 고정 → 담배를 **3단계**(불붙임 → 500틱 뻐끔뻐끔 → 꽁초 버리고 밟음)로 피우고 → 300틱 쉬고 → 반복
- **대장장이**: 망치질 A 두 번 → B 한 번 → A 세 번 → B 한 번 → 일어서기 → 반복
  → **A/B를 불규칙하게 섞는 것이 기계처럼 안 보이게 하는 장치**
- **앉아서 총 닦는 병사**: 의자에 들어간 뒤 → 두리번거림 끄고 → 닦기 A/B를 불규칙하게 섞어 반복
- **잡담하는 3인조**: 불리언 3개를 서로 넘겨가며 **한 번에 한 명만** 말하게 하는 상호배제 루프.
  말하는 동안에는 **두리번거림을 끕니다** — 그래서 대화 중인 경비 뒤로 지나갈 수 있습니다.

### 순찰 미니언어 (스크립트와 별개, 6종)

지점 이동 · 돌아서기 · 대기 · **생활 자세** · 사건 발생 · 다른 경로로 잇기

> **생활 자세**가 핵심입니다. 한 자리에서 **애니 두 개를 지정한 확률로 섞습니다.**
> 이 확률 하나가 "기계 같음"과 "사람 같음"을 가릅니다.

## 11. 우리가 가져갈 것 / 버릴 것 / 이미 앞선 것

### 가져갈 것 (구조)
1. **그림 / 가림 / 판정 / 물을 서로 다른 데이터로 분리** ← 가장 중요
2. **가림은 4단계** (있다/없다 아님)
