## 1. 한 장 요약

> **엔진은 이미 코만도스급이거나 앞섭니다. 실제 격차는 세 곳입니다 — 배경이 그림이 아닌 것, 경비가 살아있지 않은 것, 배가 도구가 아닌 것.**

그리고 이번에 확정된 두 가지 큰 사실:

**① 코만도스에는 조수가 없습니다.** 물은 화면에 구워 넣은 정적인 삼각형 메시이고, 움직이는 것은 물결 텍스처가 흘러가는 속도값 하나뿐입니다. 수위·깊이·시간축이 데이터에 아예 존재하지 않습니다. `MAREA`(조수)라는 식별자 자체가 4개 미션 어디에도 없습니다. **[실측]**
→ **우리 조수 시스템은 흉내가 아니라 원본에 없는 것입니다.** 이걸 배와 묶으면 코만도스가 못 한 것을 합니다.

**② 배는 완전히 해독됐습니다.** 좌석 배열·탑승 동작·조종 자격·정원까지 필드 이름 단위로 나왔습니다. 그대로 옮기면 됩니다.

## 2. 지시 3건을 어떻게 반영했나

### 지시 ② "코만도스 맵에 우리 에셋 올려서 원리와 시스템 그대로 이식"

**하는 것** — 원본의 **구조·수치·메커니즘**을 그대로 베낍니다.
- 그림 / 통행판정 / 가림 을 **세 개의 다른 데이터로 분리** (원본과 동일)
- 배 = 좌석 배열을 가진 컨테이너 엔티티 (원본 필드 그대로)
- 경비 = 대본 스크립트 언어 (원본 명령 20종 그대로)
- 미션 = 조건→동작 규칙 엔진 (원본 클래스 그대로)
- 검증 방법: **훈련1(TU01)·훈련4(TU04)의 구조를 1:1로 베낀 훈련 맵을 우리 아트로 만들어**, 원본 수치와 대조합니다. 이게 "이식이 제대로 됐다"는 증거가 됩니다.

**안 하는 것** — 원본의 **그림 파일 자체**를 게임에 넣지 않습니다.
- 이 저장소는 public이고, 코만도스 2는 상용 게임입니다. 배경 그림·스프라이트·음성을 그대로 실으면 저작권자 허락 없는 재배포가 됩니다.
- 기존 규칙 `docs/LOCAL_COMMANDOS_REFS.md` 와 같은 판단입니다.
- **대신 우리가 얻은 것은 훨씬 값집니다** — 포맷을 다 풀었으니, 원본이 왜 그렇게 만들었는지를 알고 우리 식으로 다시 지을 수 있습니다.

## 3. ★ 배 시스템 — 원본 완전 해독

### 3-1. 결론부터

> **코만도스의 배는 "탈것 엔티티"인 동시에 "사람을 담는 그릇"입니다.** 구역으로 순간이동시키는 게 아니라, 유닛이 배의 **자식 목록에 들어갑니다.** 그리고 이 담기 구조는 **인벤토리·수풀 은신과 완전히 같은 메커니즘**입니다. **[실측]**

### 3-2. 배 종류 [실측]

| 코드 | 이름 | 행동 클래스 | 정원 | 등장 |
|---|---|---|---|---|
| `ZODI` | 고무보트 | `ComporZodiac` | **4** | 훈련4, 섬 |
| `PATR` | 경비정 | `ComporPatrullera` | 4 | 섬 |
| `LCHM` | 모터보트 | `ComporLanchaMotora` | 4 | 잠수함 |

주목할 점: **큰 배는 탈것이 아닙니다.** 잠수함으로 탈출하는 것은 엔티티가 아니라 `CondBichosEnZona {BICHOS:"COMANDOS", ZONA:"ZONA_HUIDA"}` — 그냥 구역 판정입니다. **작은 배만 진짜 탈것입니다.**

### 3-3. 좌석 = 정원 [실측]

`HABITACULO.DATOS[]` 배열의 **길이가 곧 정원**입니다. `CAPACIDAD` 같은 숫자 필드는 어디에도 없습니다.

좌석 하나가 담는 것:
```
ENTRADA   [{ESTADO_FISICO:"FST_ANDANDO", SEC:"MONTA_LANCHA_MOTORA_SEAT_1"}]
          ← 타는 동작. 타는 사람의 "현재 물리상태"별로 다른 동작을 고름
ANIM_DENTRO   "sentado_zodiak_seat_1"    ← 앉아 있을 때 자세
XYZ_DENTRO    [-7.29, -20.0, 0.0]        ← 배 안에서의 앉는 위치
ANGULODENTRO  0.0
SALIDA    [{ESTADO_FISICO:"FST_NADANDO", SEC:"saltar_desde_zodiak"}]
          ← 내리는 동작. 고무보트에서 내리면 "헤엄치는 상태"가 됨 ★
FLAGS     ["PINT","COND"]   ← PINT=탄 사람을 그림, COND=운전석
```

### 3-4. 누가 몰 수 있나 [실측]

캐릭터마다 **조종 가능 목록(`PUEDE_CONDUCIR`)** 이 박혀 있습니다.

| 캐릭터 | 조종 가능 |
|---|---|
| **사공(LANCHERO)** | 기구·지프·**고무보트**·트럭·**모터보트**·승강기·말·의자 |
| 그린베레·저격수·스파이·도둑 | 위와 같으나 **고무보트 없음** |
| 운전병 | + 전차 |
| 공병 | + 대포·기관총좌 |
| 개(WHISKY) | 말만. 능력은 헤엄치기 하나 |

> **사공만 배를 몰 수 있습니다.** 4개 미션 전체에서 `ZODIAK`을 목록에 가진 캐릭터는 사공뿐입니다. **[실측]**
> → 우리 백도치(감나루 뱃사공)가 정확히 여기에 대응합니다.

### 3-5. 타는 절차 [실측]

```
1. 능력 확인   AUUsarVehiculo 를 갖고 있고, 배의 HABITACULO.TIPO 가 PUEDE_CONDUCIR 안에 있는가
2. 접근        PUNTOMANEJO.PUNTOS[k].POS 로 걸어가거나 헤엄쳐 감  (k = 좌석 번호)
3. 탑승 동작   HABITACULO.DATOS[k].ENTRADA 중 "지금 내 물리상태"와 맞는 동작 재생
4. 담김        유닛이 배의 BICHOS[] 자식이 됨. XYZ_DENTRO 위치에 ANIM_DENTRO 자세로 그려짐
5. 하선        SALIDA 동작. 고무보트는 물로 뛰어들어 헤엄치는 상태가 됨
```

**GSC 명령 `ENTRA_EN_HABITACULO` / `SAL_DEL_HABITACULO`** 하나로 의자·트럭·전차·대포·승강기·배를 전부 처리합니다. 경비가 의자에 앉는 것과 대원이 배에 타는 것이 **같은 코드**입니다.

### 3-6. 미션 판정도 "담김"으로 [실측]

훈련4의 미션 성공 조건이 이렇습니다.
```
CondBichosEnBichos { BICHOS:"COMANDOS", BICHO_CONTENEDOR:"ANFIBIO", NECESARIO_TODOS:1.0 }
  AND
CondBichoEnZona   { BICHO:"ANFIBIO", ZONA:"HUIDA" }
```
= "대원 **전원이** 수륙양용전차 **안에** 있고, 그 전차가 탈출 구역에 있을 것".

그리고 **똑같은 조건 클래스**를 `BICHOS_CONTENEDORES:"ESCONDITES"` 로 바꾸면 "수풀에 숨었는가" 판정이 됩니다.

> **이게 이식의 핵심입니다.** 담기(containment) 하나로 — 타기 / 숨기 / 소지품 / 시체 나르기 가 전부 표현됩니다.

### 3-7. 흔들림·물보라 [실측]

`GESTOR_ANIMACIONES` 의 `MAMBOLEO`(흔들림) 파라미터:
`LONG_MAMBOLEO_ALFA 100` `BETA 60` · `ALTURA_MAXIMA 2.05` · `VEL_ALFA 5.05 / BETA 4.59 / VERTICAL 5.48`
= 두 축으로 서로 다른 주기의 흔들림을 겹쳐서 파도 위에 뜬 느낌을 냅니다. 물보라 입자는 `POSICIONES_PARTICULAS_L/R [[32,±18,0],[-32,±18,0]]` 네 지점에서 나옵니다.

### 3-8. 고무보트는 짐이다 [실측]

훈련4에서 사공은 고무보트를 **소지품으로 갖고 다닙니다**.
`LANCHERO.CONTENEDOR = 1.0` · `LANCHERO.BICHOS = [ZODIAK, PISTOLA_LA, CUCHI_LA]`

## 4. ★ 물 시스템 — 그리고 조수가 우리 고유인 이유

### 4-1. 원본의 물은 무엇인가 [실측]

`.H2O` 파일을 완전히 해독했고, 물 그림을 복원해서 확인했습니다.

```
u32 몸체수(=4)   ← 카메라 4회전 각각 하나씩
u32 버전
u32 오프셋[4]
u8  물결 텍스처 256×256 (8비트 팔레트, 실사용 242색)
u32 팔레트[256]  (RGB565)
몸체마다:
  정점 626~636개 : 화면좌표(sx,sy) + 텍스처좌표(u,v) + 물결 위상 2개
  삼각형 1065~1133개 : 정점 3개 + 미리 계산한 변 벡터 6개 + 깊이정렬키
  스캔라인 907~1107줄, 스팬 32,382~35,340개  ← 미리 래스터화해 둔 것
```
**산술 검증**: `40 + 40×정점수 + 76×삼각형수 + 8×줄수 + 6×스팬수` 가 네 몸체 전부 실제 크기와 **정확히 일치**합니다.

즉 원본의 물은 **화면 좌표에 미리 구워 넣은 삼각형 판**입니다. 격자도, 높이맵도, 마스크도, 애니 프레임도 아닙니다.

### 4-2. 움직이는 것은 딱 하나 [실측]

`TU04.BAS`:

### 4-3. 조수는 없다 — 확정 [실측 · 부정 확인]

- 정점 기록의 마지막 4개 float은 **모든 몸체의 모든 정점에서 0**입니다. Z좌표가 없습니다.
- `MAREA`(조수) · `NIVEL_AGUA`(수위) · `PROFUNDIDAD`(깊이) 라는 식별자가 훈련1·훈련4·섬·잠수함 **어디에도 없습니다**.
- 규칙 엔진의 조건 10종·동작 6종 중 **물을 건드리는 것이 하나도 없습니다**.
- 수면 높이는 오직 **배 자신의 흘수선**으로만 나옵니다 (`ComporZodiac.VEL_ALTURA_AGUA_HUNDIENDOSE` = 가라앉을 때 수면이 올라오는 속도).
- 물 모양을 바꾸는 유일한 방법은 **다른 H2O 파일로 통째 교체**하는 것입니다 (`_SUST` = sustitución, 치환). 일회성 A→B 스위치이지 연속 변화가 아닙니다. **[추정 — `_SUST` 파일 자체는 미열람이나, 포맷 구조상 다른 방법이 불가능함]**

> **결론: 미션 내내 연속으로 변하는 수위는 코만도스 엔진에 없습니다. 우리 조수는 진짜 고유합니다.**
> 그러니 **조수를 지키는 것이 최우선 원칙**입니다. 격자를 다각형 navmesh로 바꾸면 조수 공식(`깊이 = 수위 − 타일높이`)이 무너집니다. 바꾸지 않습니다.

### 4-4. 물 판정은 어디에 있나 [실측]

`.SEC`의 섹터 플래그 `+4` 바이트가 `(클래스 << 8) | 하위` 로 쪼개집니다.

| 클래스 | 개수 (훈련4) | 높이(altura) | 뜻 |

| 0 · 1 · 2 · 5 | 149 | −0.0 및 양수 | 땅 (종류별) |
| **13** | **2** | **−57.5 / −82.3** | **깊은 물** |
| **14** | **10** | **−48.0 전부** | **물** |

## 8. ★ 새 스토리 — 배가 도구가 되는 구조

### 8-1. 지금 스토리의 문제

배가 **마지막 한 번, 탈출용으로만** 쓰입니다. 그래서 백도치(뱃사공)는 "마른 땅에서 특기 없음"인 채로 게임의 90%를 보냅니다.

### 8-2. 새 뼈대 — 한 줄

> **물이 차오르는 여섯 시간 동안, 배 한 척으로 사람들을 실어 나른다.**

### 8-3. 왜 이게 코만도스를 넘어서는가

원본 훈련4는 **"강을 건너 → 탈것을 훔쳐 → 타고 나간다"** — 한 번 건너면 끝입니다. 물이 안 변하니까요.

우리는 물이 변합니다. 그래서 **같은 길이 시간에 따라 열리고 닫힙니다.**

| 조수 | 갯벌 | 배 | 그래서 |
|---|---|---|---|
| **간조** 0~25% | 걸어서 건널 수 있음 | **못 뜸** (물이 얕아 좌초) | 발로는 가는데, 사람을 실을 수 없다 |
| **들물** 25~65% | 잠기기 시작 | 갯골로만 다님 | **여기가 유일한 겹치는 구간** |
| **만조** 65~100% | 완전 침수 | 어디든 감 | 배만이 길. 못 탄 사람은 못 나간다 |

> **전반부는 발로, 후반부는 배로. 그 전환점을 놓치면 갇힙니다.**
> 이건 조수와 배가 둘 다 있어야만 성립하는 긴장이고, 코만도스에는 없습니다.

### 8-4. 배의 세 가지 역할

원본이 확인해 준 "담기(containment)" 하나로 셋 다 됩니다.

| 역할 | 원본 대응 | 우리 |
|---|---|---|
| **이동** | `PUEDE_CONDUCIR` 화이트리스트 | **도치만** 조종 가능 |
| **운반** | `HABITACULO.DATOS[]` 좌석 배열 | 좌석 **4칸** → 주민 12명이면 **최소 3번 왕복** |
| **은신** | `CondBichosEnBichos {BICHOS_CONTENEDORES:"ESCONDITES"}` | 거적 아래 숨기 (경비가 못 봄) |

### 8-5. 3막

**1막 — 상륙 (간조, 0~25%)**
해무 속에서 갯벌에 배를 대고 내린다. 물이 얕아 배가 못 뜬다 → **갈대밭에 배를 숨긴다**(은신). 걸어서 어촌·염전을 지나 구호소로 접근. 실종 조사관의 흔적을 찾는다.
*이 막의 교훈: 배는 지금 짐이다.*

**2막 — 잠입 (들물, 25~65%)**
구호소에 들어가 증거를 모으고 지하 취조실의 정필재를 구출한다. 물이 차기 시작해 **갯길이 하나씩 잠긴다** — 왔던 길로는 못 돌아간다. 배가 뜬다. 수문을 열면 동굴 구역만 배수(기존 시스템).
*이 막의 교훈: 이제 배가 유일한 길이다.*

**3막 — 실어 나르기 (만조, 65~100%)**
백석섬 감금실의 주민들을 배로 나른다. 좌석 4칸이라 **왕복**해야 한다. 왕복할 때마다 물은 더 차오르고, 경비는 배를 찾기 시작한다.
엘리어스 베일이 **마지막 배를 노린다.** 배를 잃으면 남은 사람은 못 나간다.
*이 막의 교훈: 몇 명을 태워 나갔는가가 곧 점수다.*

### 8-6. 배가 만드는 새 긴장 4가지

1. **왕복 = 노출.** 같은 물길을 세 번 지나면 경비가 알아챈다. 갯골을 바꿔 가야 한다.
2. **정원 = 선택.** 4칸에 누구를 태울 것인가. 다친 주민? 정필재? 장부?
3. **배를 숨기기.** 정박한 배를 들키면 부서지거나 감시가 붙는다.
4. **도치가 배에 있으면 육지에 없다.** 4명 중 1명이 조타에 묶인다 — 코만도스의 "한 명이 차에 타면 그 사람은 못 싸운다"와 같은 문법.

### 8-7. 등급 재설계 (기존 공식 확장)

기존: 증거×7 + 구출비율×20 + 설화×4 + 베일 14/6 + 무경보 12 + 무살상 8 + 시민무사 8 + 민심×6 − 시민사망×9

**추가/변경**
- `구출비율` = **배에 실어 나간 사람 수 ÷ 전체** (구출만으로는 안 됨. 태워 나가야 함)
- **배 보존** +10 (배가 온전히 살아남음)
- **최소 왕복** +6 (3회 이하로 끝냄 = 동선 효율)
- **물때 실패** −12 (만조에 육지에 갇힌 대원 1인당)

## 9. 맵 재설계 — 물길이 뼈대

지시 ③에 따라 맵을 다시 짭니다. 기존 좌표계·크기(96×96)·조수 공식은 유지합니다.

### 9-1. 설계 원칙 3가지

1. **갯골(수로)이 도로다.** 배가 다니는 길을 먼저 긋고, 그 다음에 육지를 배치한다. 원본 훈련4가 강을 대각선으로 놓고 그 양쪽에 시작점·목표·탈출을 배치한 것과 같은 방식.
2. **간조 길과 만조 길이 달라야 한다.** 같으면 조수가 의미 없다. 겹치는 구간을 의도적으로 좁게 만든다.
3. **왕복 동선이 3가지 이상.** 한 길만 있으면 3막이 반복 노동이 된다.

### 9-2. 구조 (기존 대각선 좌표계 `s = tx+ty` 유지)

```
        절벽 s<58            봉수·감시
        ───────────────
        본토 s<110           어촌 · 백해구호소 · 염전·갈대
        ───────────────
        해변 s<124           선녀바위 · 배 숨기는 곳 ★
        ───────────────
        갯벌 s<166           ← 조수가 지배하는 층 ★
        ───────────────
        바다                 백석섬(74,76 r10.6) · 해식동굴(86,84 r10.2)
```

**새로 추가할 것**
| 요소 | 개수 | 역할 |
|---|---|---|
| **갯골(수로)** | **3줄** | 배가 다니는 길. 깊이가 달라 뜨는 물때가 각각 다름 |
| **정박지** | **4곳** | 배를 대는 곳. 은폐도·경비 시야가 각각 다름 |
| **물때 표지** | 6곳 | 지금 수위에서 여기가 잠기는지 눈으로 알려줌 |

### 9-3. 검증 맵 — 원본 구조 1:1 복제 (이식 증명용)

**"훈련장" 맵을 별도로 하나 만듭니다.** 원본 훈련1·훈련4의 구조를 그대로 베끼되, 그림과 오브제는 100% 우리 것으로 채웁니다.

|---|---|
| 담배 피는 병사 | 곰방대 무는 신도 |
| 담배갑 뒤져서 던지기 | 향주머니 뒤져서 던지기 |

**왜 만드는가**: "원리와 시스템이 그대로 이식됐다"를 **증명**하기 위해서입니다. 원본과 같은 상황을 우리 엔진에서 재현해 보면, 빠진 메커니즘이 즉시 드러납니다. 그리고 그대로 **튜토리얼**로 씁니다.

### 【1단계】 배 — 격차 C · 새 스토리의 토대 ★최우선

**왜 1번인가**: 스토리·맵·등급이 전부 배 위에 얹힙니다. 이게 없으면 뒤가 다 헛돕니다. 그리고 원본 해독이 끝나서 **설계할 게 없습니다 — 옮기기만 하면 됩니다.**

**설계 (원본 필드 그대로 대응)**
```
배 엔티티 {
  종류      "나룻배"
  조종자격  ['dochi']                  ← 원본 PUEDE_CONDUCIR
  좌석[4] {
    타는동작  {걷는중: '올라타기', 헤엄중: '기어오르기'}   ← 원본 ENTRADA
    앉은자세  '앉음_0'                                    ← 원본 ANIM_DENTRO
    안쪽위치  [dx, dy]                                    ← 원본 XYZ_DENTRO
    내리는동작 {물: '뛰어내리기→헤엄', 뭍: '내려서기→걷기'} ← 원본 SALIDA
    깃발      ['그림', '조타석']                          ← 원본 FLAGS PINT/COND
  }
  접근지점[4]                                             ← 원본 PUNTOMANEJO
  흔들림 {길이A 100, 길이B 60, 최대높이 2.05,
          속도A 5.05, 속도B 4.59, 수직 5.48}              ← 원본 MAMBOLEO 수치 그대로
  물보라지점 [[32,±18],[−32,±18]]                          ← 원본 그대로
  최소수심 0.22        ← ★우리 고유. 이보다 얕으면 좌초
}
```

**담기(containment) 구조를 먼저 만듭니다.** 원본이 이걸로 타기·숨기·소지품·시체나르기를 전부 처리하므로, 여기서 만들면 4단계(격차 F)가 거의 공짜가 됩니다.
```
유닛.담긴곳 = 배 | 수풀 | 다른유닛(업힘) | null
조건: 담긴것들이(대상들, 그릇, 전원필요?)   ← 원본 CondBichosEnBichos 그대로
```

**조수 연동 (우리 고유)**
- `배가뜨는가 = (수위 − 그칸높이) > 0.22`
- 안 뜨면 좌초. 도치가 밀어서 갯골까지 옮길 수 있음(느림·소음 큼)
- 정박 중 은폐도 = 그 칸의 은폐도. 갈대밭 정박이 안전

**완료 판정** (자동 테스트 8개)
1. 도치가 좌석0에 타면 조타 가능, 해주가 타면 승객으로만 탑승
2. 주민 4명 태우면 5번째는 거부
3. 만조에 배가 갯벌 위를 지나가고, 간조에 같은 칸에서 좌초
4. 하선 시 물이면 헤엄 상태, 뭍이면 걷기 상태
5. 갈대밭 정박 시 경비 시야 안에서도 30초간 미발각
6. 배가 부서지면 탄 유닛 전원 물에 빠져 헤엄 상태
7. `담긴것들이(대원 4명, 배, 전원필요)` 조건이 정확히 작동
8. 기존 플레이 테스트 32개 전부 통과 (회귀 없음)

**규모**: 담기 구조 약 120줄 + 배 약 220줄 + 조수연동 약 60줄 = **약 400줄** [추정]

### 【2단계】 배경을 그림으로 — 격차 A·D 동시 해결

**왜**: 첫인상의 90%. 가림(D)이 여기 얹혀 옵니다.

**어떻게 — 원본과 같은 방식** (원본이 3D로 만들어 구웠다는 증거: 나무 그림자 방향·길이 일관 / 4회전 전부 저장 / 가림 폴리곤이 평면식을 가짐)

```
[입력]  96×96 높이 데이터 (이미 있음) + 건물 34동 GLB + 소품 GLB + 지형 재질
   ↓
[3D 씬 조립]  우리 공식 그대로: isoX=(tx−ty)×32 , isoY=(tx+ty)×16 − 높이×20
   ↓
[직교 렌더 1회]  방위각 45° / 고도 30°  (기존 베이커와 동일)
   ↓
[출력 3장]  ① 컬러 6144×3072 → 배경
            ② 깊이맵         → 가림 (원본 MA2 대응)
            ③ 그림자맵       → 분위기
   ↓
[64×64 조각 4,608개]  → 기존 청크 LOD에 그대로 물림
```

**핵심**: 배경은 **판정을 전혀 모릅니다.** 걷기·시야·조수는 지금처럼 96×96 격자가 100% 담당합니다.
→ **원본과 정확히 같은 구조입니다** (그림 Y64 / 판정 SEC / 가림 MA2 세 파일 분리).
→ 예전에 "맵을 그림 한 장으로 받으면 안 된다"고 했던 이유는 **그림으로 판정까지 하려 할 때만** 생기는 문제입니다. 분리하면 사라집니다.

**가림 4단계**: `대원 화면깊이 > 배경 화면깊이` 인 픽셀에서 대원을 4단계로 흐리게. 원본 2비트 마스크와 같은 결과.

**물 렌더링**: 원본 H2O가 준 교훈 — **물은 미리 구운 삼각형 판 + 흐르는 텍스처**입니다. 우리는 조수로 수위가 변하므로 삼각형을 구울 수 없지만, **물결 텍스처 흘리기(SPEEDAGUA)** 는 그대로 씁니다. 지금 깊이 7버킷 Path2D 위에 흐르는 텍스처를 얹으면 됩니다.

**완료 판정** (자동 테스트 6개)
1. 배경 조각 4,608개 생성, 이음새 픽셀차 < 자연 인접차 ×2
2. 배경 깐 상태로 기존 플레이 테스트 32개 통과 (= 판정 불변 증명)
3. 만조에 갯길이 여전히 잠김 (배경 불변, 물만 덮임)
4. 나무 뒤 통과 시 대원 알파가 0/1이 아닌 중간값
5. 1600×900에서 30fps 유지
6. 배경 파일 없어도 코드 렌더로 폴백

**규모**: 베이커 약 400줄 + 렌더러 약 200줄 [추정]
**진짜 비용은 코드가 아니라 3D 에셋** — 건물 34동 + 소품 GLB. 이게 트라이포 작업 분량입니다.

## 12. 하지 않을 것

1. **격자 → 다각형 navmesh 전환 안 함.** 원본은 navmesh지만 우리 조수 공식(`깊이 = 수위 − 타일높이`)이 격자 높이에 물려 있습니다. 바꾸면 **원본에 없는 우리 유일 시스템**이 무너집니다. 원본도 그림과 판정이 분리돼 있으므로, 판정이 격자여도 그림은 동급이 됩니다.
2. **원본 코덱(Y64 / MA2 / H2O) 흉내 안 냄.** 2001년엔 JPEG/PNG가 마땅치 않아 직접 만든 것입니다. 우리는 JPG/WebP를 씁니다. **포맷을 해독한 목적은 베끼는 게 아니라 설계 의도를 아는 것**이었습니다.
3. **익사·산소 타이머 안 넣음.** 원본에 없습니다. 물속 긴장은 조수와 적으로 만듭니다.
4. **총격전·살상 없음.** 무살상 보너스(+8)가 정체성.
5. **멀티플레이·외부 라이브러리 없음.**
6. **코만도스 원본 파일은 GitHub에 올리지 않습니다.** 이 저장소는 public이고 원본은 상용 게임 자산입니다. 이 문서에 있는 것은 우리가 측정한 **수치와 구조**뿐입니다. (`docs/LOCAL_COMMANDOS_REFS.md` 규칙 유지)
